# Digest, routing, and run records

Use enough structure to preserve evidence and next steps. Omit empty sections; a short finding does not need several paragraphs. Write ordinary descriptive labels rather than mandatory emoji or hype.

## Dimension digest

```text
Dimension name and number — date
Period covered:
Input pages/exports and accessible coverage:
Primary sources read and collection limits:

Executive signal: the main finding and practical implication

Findings, as needed:
  Claim and what changed
  Evidence status, primary source, date, population/task and measure
  Relevant current course module or skill
  Interpretation, counterevidence and limits
  Comparison with previous findings
  Useful framework, if it improves the analysis
  Proposed action: course / skill / interview / editorial / further research

URL library:
  Priority reading — title, URL, why it matters, read/unread status
  Reference — title, URL, category, read/unread status

Pattern review:
  Supported or strengthened, with independent sources identified
  Narrowed or contradicted, with implications
  New hypotheses, scope and test
  Promotion candidates requiring the applicable governance decision

Cross-dimensional connections, when supported
Thought-leadership seeds, when useful:
  Working title, argument, evidence, alternative explanation, intended medium

Impact:
  Course module | specific change | priority | add/update/contradict | proposed/applied
  Skill | proposed change | evidence and limits | apply/hold/investigate | actual version if applied
  Knowledge record | entry | proposed/applied action | authority and evidence

Coverage completed and remaining
Counts of distinct collected entries and underlying sources
Next dimension or action, with reason
```

Do not label Grok+Perplexity agreement “verified” without checking the underlying claim. A pattern's support count excludes mere repetition and distinguishes extensions from confirmations.

## Weekly or requested-cycle roll-up

Retain these nine output families when relevant:

1. Most important signals across processed dimensions, normally up to five.
2. Supported cross-dimensional connections.
3. Strong editorial ideas, normally up to three, without a novelty quota.
4. Priority links by category and reading status.
5. Interview implications where relevant, clearly distinct from Ravi's own experience.
6. Course currency view, using the actual current module inventory; the former seventeen-module map is a reference, not a verified current count. Define current/needs-review/stale from content and changes, not age alone.
7. Skills actually updated and separately proposed updates.
8. Actual knowledge-record changes and candidates awaiting a decision.
9. Collection/prompt improvements tied to an observed gap, with a concrete suggested revision.

A partial cycle identifies included dimensions and unavailable inputs. Do not imply a scheduled weekly run occurred from the date in a filename.

## Output locations and current-path checks

| Record | Stored convention or route | Write condition |
|---|---|---|
| Dimension digest | `3_Research/weekly-digests/YYYY-Wxx-DIM-N-name.md` | Legacy path: locate current home or establish one within the authorized task; absent at this revision |
| Weekly roll-up | `3_Research/weekly-digests/YYYY-Wxx-SYNTHESIS.md` | After the requested coverage, with completeness stated |
| Run log | `3_Research/weekly-digests/SYNTHESIS-RUN-LOG.md` | After checked output; preserve partial boundaries |
| Hypothesis | `5_Knowledge/hypotheses.md` | Authorized evidence update, preserving source independence and challenges |
| Rule | `5_Knowledge/rules.md` | Actual approved promotion or authorized rule revision, never mention-count automation |
| Course signal | Current relevant course `CONTEXT.md` | Concrete impact within scope; distinguish proposed/applied |
| Skill change | Canonical skill + current registry/change log | After revision, version, checks and synchronization |
| Interview signal | Current context under `1_Projects/0_interview-prep/` | Relevant sourced preparation within scope |
| Editorial seed | Inside the dimension digest | Only when the argument has a defensible basis |
| Collection prompts | Legacy `3_Research/x-research/prompts/` and `perplexity-research/prompts/` | Neither old path existed at this revision; locate current configuration before editing |

`YYYY-Wxx` uses the intended ISO week-year. Add a run identifier or preserve revision history if several outputs for the same dimension/week would collide. File naming must not overwrite a prior digest silently.

## Run log

The original columns remain useful:

| Date | Dimension | Notion Pages Read | New Content Found | Output File | Key Findings Summary |
|---|---|---|---|---|---|
| Actual run date | Number and name | Verified IDs/names or export paths | Yes/no/material revision | Saved file | Concise finding |

Also record the processed date/entry boundary, content fingerprint where available, status (complete/partial/no change), remaining work, and inaccessible sources. A no-change record does not claim new synthesis; a partial record does not advance a complete coverage marker.

## Invocation examples

- “Synthesise context engineering”: dimension 2; resolve the Grok Pulse and Perplexity Context Engineering Research IDs, then process the available new range.
- “Run full synthesis”: all ten, sequentially, with coverage checkpoints and a final roll-up.
- “What patterns are emerging?”: inspect hypotheses and recent relevant digests, then report evidence changes; a full collection run is unnecessary unless requested.
- “Connect the dots on this topic”: search relevant accessible collections and prior findings, trace primary sources, and produce a bounded connection report.
