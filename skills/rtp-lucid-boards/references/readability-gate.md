# Readability inspection

Inspect the actual exported or explicitly reconstructed asset at its intended destination size. Record **pass, fail, not applicable, or not tested**, with evidence where useful. Use this as the Print producer perspective within [the shared review](judge-panel.md).

Session / page: ______  Asset and revision: ______
Use and placed dimensions: ______  Reviewer and method: ______

| Check | Result / evidence |
|---|---|
| 1. The main claim is the first clear reading target at the intended distance or handout size. | |
| 2. Copy is concise: check the 12-word claim target and preserve needed meaning when explaining an exception. | |
| 3. Record source units, smallest meaningful source type, scaling, and delivered size. The historical 24-point source minimum alone is not a print-size check. | |
| 4. Automatic fitting or layout has not shrunk, clipped, or displaced the intended text. | |
| 5. Every text/background pair has sufficient contrast for the use; use calculated values and visual inspection. | |
| 6. Avoid weak pairs such as white on bright yellow/gold or ink on the specified blue. Inspect actual colors rather than hue names. | |
| 7. The small palette has a clear purpose; count saturated families and remove unnecessary decoration. | |
| 8. An inspected grayscale copy preserves all meaningful distinctions through lightness, labels, borders, or other encoding. | |
| 9. Supporting copy fits comfortably; check the 40-word-per-field starting target without deleting essential qualification. | |
| 10. The chosen comparison, ladder, matrix, table, or other justified layout expresses the real relationship. | |
| 11. Shapes and text have no unintended overlap, clipping, missing glyphs, or ambiguous connections. Intentional grouping and layering are allowed. | |
| 12. The takeaway is clear, and any necessary source or caveat remains available in the delivered context. | |
| 13. `LUCID.md` records the real document IDs/URLs where present, local assets, sizes, provenance, and current review status. | |

A failed required check needs a specific repair. An untested required condition remains pending. Neither should be converted into a pass by averaging, imagination, or an earlier review of a different file. Save the current work and keep unrelated preparation moving while resolving the issue.
